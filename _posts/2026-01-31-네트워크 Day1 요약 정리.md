# 1. 인터넷 구성 요소

- 인터넷
	- host -> LAN -> ISP -> 백본망 -> 서버네트워크
	- 라우터 + 링크로 이루어짐

- host
	- 데이터 생성/소비

- ISP (Internet Service Provider)
	- 통신사
	- 혹은 통신사가 운영하는 네트워크 망
	- 하는 일 : LAN을 인터넷에 업링크

- 백본망 (Backbone)
	- 수많은 고성능 라우터들이 연결된 초고속 핵심 구간

- 라우터 (Router)
	- IP 주소를 보고 경로를 결정(Routing)
	- 패킷을 Hop 단위로 전달
	- L3 네트워크 계층 장비

- 링크 (Link)
	- 데이터가 실제로 지나가는 길
	- L1 물리계층 장비

# 2. 네트워크 통신 핵심 개념

## 1. 패킷
	- 뭘 보낼건데?
		> 패킷이요
- 패킷 : 최소 전송 단위

- 패킷화 왜 했냐고?
	- 혼잡 방지
	- 부분 재전송
	- 유연한 경로 선택

- 근데 패킷화 하니까...
	- 순서가 바뀌거나, 지연이 발생하거나, 유실 되기도.
	- 재조립 필요

- 그래서 이 단점 해결 위해 TCP 등장
	- TCP -> 순서 보장, 누락된 패킷 재전송

## 2. 라우팅 (Routing)
	- 어디로 보낼건데?
		> 라우터가 정한대요

- 라우팅
	- 내비게이션 역할
		- DNS가 IP를 알려주면 
		- 라우팅은 IP주소를 보고 어떤 경로로 어떻게 갈지 결정
	- Hop
		- 데이터는 한번에 도착하지 않고 한 홉 한 홉씩 이동


## 3. 프로토콜 (Protocol)
	- 어떻게 보낼건데?
		> 프로토콜에서 하라는대로요
- 프로토콜 : 약속

- 프로토콜 예시
	- 응용 계층 (L7) : HTTP, DNS
	- 전송 계층 : TCP/UDP
	- 네트워크 계층 (L3) : IP
	- 데이터링크 계층 : 이더넷, Wi-fi

# 3. 주소 체계

1) IP 주소
	- 인터넷에서 컴퓨터 구분하기 위한 주소 (유일해야함) 
		- ex) 강원도 영월군 김삿갓면 xxx길 yyy zzz호
	- 체계
		> IPv4
		> 	ex) 192.168.0.10
		> IPv6
		> 	ex) 2001:db8: :
		> 	- 기기가 너무 많아서 만든 주소


2) MAC 주소
	- 하드웨어에 박혀있는 주소
		- ex) 김철수
	- 직접 연결된 네트워크 구간에서 장비를 구분하는 물리적 주소
	- 라우터를 지날때마다 다음 구간의 MAC주소로 교체됨

3) Port 번호
	- 해당 호스트의 어떤 서비스로 갈지 정함

4) DNS (Domain Name System)
	- 도메인을 IP 주소로 번역
	- 해당 서비스를 제공하는 서버이기도 하지만 동시에 프로토콜(L7)이기도 함

5) ARP
	- 근거리 네트워크에서 다음 Hop의 IP 주소를 가지고 MAC 주소를 알아냄

# 4. 계층 모델
- 고장시 원인을 빨리 찾기 위해 구분

1) 종류

| OSI      | TCP/IP                |
| -------- | --------------------- |
| L1, L2   | Network Access (Link) |
| L3       | Internet              |
| L4       | Transport             |
| L5,L6,L7 | Application           |

2) 계층 설명명
	- L1 = Physical Layer (물리 계층)
		- 역할
			- 실제로 데이터를 물리적으로 전송
		- 장비
			- 전기신호, 랜선, 광케이블, Wi-Fi 등
	
	- L2 = Data Link Layer (데이터 링크 계층)
		- 역할
			- 네트워크 계층이 결정한 목적지(네트워크 계층 입장에서 다음 홉) MAC 주소로 데이터를 전송
			- 필요시 ARP를 사용해 MAC 주소도 확인
		- 장비 
			- 스위치
				- 근거리 네트워크 (LAN) 전용
				- MAC 주소 사용
	
	- L3 = Network Layer (네트워크 계층)
		- 역할
			- 목적지 IP와 라우팅 테이블을 기반으로, 다음 홉(next Hop) IP를 결정
		- 장비
			- 라우터
				- IP 주소 사용
	
	- L4 = Transport Layer (전송 계층)
		- 역할
			- 포트번호와 통신 규칙(end-to-end)(호스트<->호스트) 담당
		- 사용 프로토콜
			- TCP (Transmission Control Protocol) : 연결형 전송 계층 프로토콜
				- 연결 설정시 3-way handshake 사용 (연결을 확인함)
				- 신뢰성 있는 전송 (재전송, 순서 보장)
				- 웹, 로그인시 주로 사용
			- UDP (User Datagram Protocol) : 비연결형 전송 계층 프로토콜
				- 연결 확인 없음, 재전송 없음, 순서 보장 없음
				- 빠름
				- 스트리밍, 실시간 통신시 사용
	
	- L7 = Application Layer (응용 계층)
		- 사용자가 직접 사용하는 영역
		- 사용 프로토콜
			- HTTP : 요청/응답 프로토콜
			- HTTPS : HTTP + TLS(암호화)

# 5. 네트워크 진단 및 실습

1) ping
	- L3 (네트워크 계층) 진단
	- IP 진단 (해당 IP까지 도달 가능한지 확인)
		- 일단 가는 길이 있긴 하다
	- 사용법
```shell
ping 8.8.8.8
ping google.com
```

2) traceroute
	- L3 (네트워크 계층) 진단
	- 패킷이 거치는 Hop 경로를 직접 확인 (목적지까지의 라우터 목록 확인)
		- 중간에 몇 번째 라우터에서 막히는지 확인
	- 사용법
```shell
# 리눅스/맥
traceroute google.com

#윈도우
tracert 8.8.8.8
```

3) nslookup
	- L7 (응용 계층) 진단
	- 도메인 이름을 IP주소로 바꿔주는 DNS가 제대로 작동하는지 확인
	- 사용법
```shell
nslookup google.com
```

4) nc / Test-NetConnection
	- L4 (전송 계층) 진단
	- 특정 포트가 열려있는지 확인
	- 사용법
```shell
# 리눅스
nc -zv google.com 80

# 윈도우 PowerShell
Test-NetConnection -ComputerName google.com -Port 80
```

5) curl
	- L7 (응용 계층) 진단
	- 실제 요청 보내고 응답 받는 전체 대화 과정 확인
	- 사용법
```shell
curl http://google.com
```

- 진단순서
	- ping / traceroute(길있는지 확인, 길에 문제없는지 확인) -> nslookup (원하는 곳에 도착했는지 확인) -> nc (도착한 곳에서 제대로 받고있는지 확인) -> curl (도착한 곳이 제대로 반응하는지 확인)
